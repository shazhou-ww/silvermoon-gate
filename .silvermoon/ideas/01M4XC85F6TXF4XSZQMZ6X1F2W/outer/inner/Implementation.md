# Implementation

## Steps

### I-S01: 实现可靠签发与状态

固定 JCS/摘要封装和版本化签名 claims，D1 决定/审计/outbox 原子写入，签名在提交后可重复安全恢复；UI 显式展示签发状态。

### I-S02: 实现独立验证与信任包

交付独立验证器、版本化信任包及 keyId 状态规则，调用方明确预期摘要、approved 与快照新鲜度策略。

### I-S03: 验证协议与恢复兼容性

交叉实现测试签名/摘要，覆盖任务重试、密钥轮换/泄露、旧快照、失败恢复以及既有无签名历史，不扩大前阶段授权范围。

## Acceptance criteria

### I-AC01: 决定与签发状态一致

目标 Worker/D1 故障注入证明 outbox 不漏写，重试不改变 Decision、不覆盖已保存凭证；浏览器展示待签发/失败/就绪。

### I-AC02: 验证器不误放行

跨实现向量证明只有批准、签名有效、摘要匹配及快照合格通过；错误算法、拒绝、泄露和过旧快照全部拒绝。

### I-AC03: 前阶段与历史保持可用

回归证明在线调用/人类流程未破坏；历史缺失凭证明确标注而非伪签发，密钥状态与验证结果包含快照版本。
