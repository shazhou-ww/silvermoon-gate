# 目标 UX 设计

本文是 [Idea.md](Idea.md) 的产品体验设计，不沿用半成品页面或 API 约束。
[目标体验示意](ui-review/index.html)
是独立、无构建的审阅辅助，不是生产 UI，也不宣称已实现后端能力。

## 产品原则

让用户先回答三个问题：**需要我决定什么？我凭什么权限决定？我的决定产生了什么结果？**
登录、权限配置和密码学细节服务于这三个问题，而不是占据产品首页。

## 信息架构

| 入口                 | 面向谁                    | 核心内容                                                               |
| -------------------- | ------------------------- | ---------------------------------------------------------------------- |
| 待我审批（默认首页） | 审批人                    | 待处理请求、业务标题、请求方、模板、权限上下文；可筛选，服务端授权分页 |
| 我的请求             | 请求方                    | 新建入口、等待/终态、撤回、新建重试；按 Thread 查看关联历史            |
| 模板                 | 请求方 / 模板管理员       | 可使用的版本与说明；管理员发布新版本、修改当前名单，分别授权           |
| 权限与身份           | 权限所有者 / Agent 管理者 | 身份绑定、Agent 注册、Delegate 范围、Grant 接收方/期限/撤销            |
| 验证与审计           | 调用方 / 有权审计的人     | 凭证导出、验证解释、不可变事件与授权证据                               |

不把“系统管理员”做成自动可看全部载荷的超级角色。菜单可见性只是提示，真实授权在服务端。没有权限的请求统一显示“不可访问或不存在”。

## 核心流程

### 发起请求

选择明确的模板版本 → 根据模板 schema 填写字段/导入 JSON
→ 核对业务摘要和原始载荷 → 创建并进入详情。创建前显示版本、提交者与载荷范围；服务器执行完整 JSON
Schema 校验并计算摘要。创建后不能编辑；拒绝/撤回后以新请求重试。

一次提交使用一个幂等键。双击或网络超时后的原样重试复用同一键；修改内容要产生新键。幂等冲突清楚说明原因，不静默重复创建。

### 审批与确认

详情按阅读顺序呈现：

1. 状态、业务标题、请求方、模板版本及创建时间。
2. 模板定义的业务字段摘要，原始 JSON 与完整摘要可展开核对。
3. **实际操作者**、**权限主体**、直接/委托方式；委托时显示范围、Grant 期限与授权链。
4. 批准与拒绝，彼此明确、不默认选择批准。二次确认重述请求与载荷，提醒首个合格决定生效且不可修改。

模板要求更强认证时，确认前完成 step-up，并在服务端验证新认证证据；不能仅让用户点“我已验证”。敏感/破坏性动作使用可访问的内联确认或对话框，不依赖 toast。

### 等待、竞争与恢复

- pending 没有自动批准/自动超时。页面提供手动刷新，后台采用可取消、隐藏暂停、失败退避的轮询；初期不要求 WebSocket。
- 冲突后重新获取获授权的真实状态：“另一审批人已拒绝/请求方已撤回”，移除决定按钮，不把点击动作显示成成功。
- Grant 过期、撤销、名单移除或身份封存：显示权限失效；若读取也无权限，不保留可见载荷。
- 提交超时后先查询状态，仍 pending 时重新核对再确认，不盲目重试决定。状态无法读取时显示“结果尚未确认”。

### 凭证与离线验证

明确区分“已批准·凭证待签发”“已批准·凭证可下载”“已批准·签发失败待恢复”。没有凭证不能称作可离线放行。

验证结果逐项呈现 outcome、签名、预期摘要匹配、keyId 状态、trust-bundle 版本/新鲜度。拒绝的有效凭证、错误摘要、泄露密钥或不合格快照都不能显示绿色“可放行”。离线验证由接入方独立执行，不依赖 Gate 页面。

## 权限管理体验

先选可委托操作与资源范围，再选接收 Identity 和有效期；显示收窄后的范围，禁止超出自身权限，默认不允许转委托。Delegate 范围变更创建替代实体，提示原 Grant 不会自动迁移。撤销 Grant 时说明只影响未来操作，不改写历史凭证。Agent 凭据只在签发时展示，后续允许轮换而不是找回明文。

## 子页面设计

下列路径是拟议产品路由，不是当前已实现 API。列表仅服务端授权分页，筛选改变后回到第一页；分页和筛选不扩张权限。所有管理写操作都在提交时重新验证权限，未提交草稿不默认持久化敏感载荷。

### 我的请求与新建请求

- `/requests/mine`：默认按创建时间倒序，以业务标题为主，展示模板版本、状态、创建时间和凭证状态；按状态、模板、Thread 筛选。空列表引导新建，失败提供重试，不以“无请求”掩盖失败。
- `/requests/new`：三步“模板 → 载荷 → 核对”。模板选择只列出可使用版本，明确显示停用与 schema/MFA 要求；切换版本时提示需要重新校验，保留草稿但不得直接提交旧校验结果。
- 表单字段和 JSON 导入是同一载荷的两种编辑方式；无法映射字段时使用 JSON 模式，禁止静默丢弃未知字段。核对页展示完整快照与摘要，客户端摘要仅辅助核对，最终以服务器结果为准。
- 提交禁用重复按钮；网络结果不明保留幂等键，查询或原样重试。字段失败返回对应输入，幂等冲突明确链接到有权访问的原请求。
- `/requests/:id`
  请求方视图：pending 可内联确认撤回；说明“不再接受决定，但不删除历史”。竞争失败刷新终态。拒绝/撤回提供“基于此请求新建”，复用草稿而不复用 request
  ID/幂等键；已批准显示凭证待签发/失败/可下载。
- `/threads/:id`
  只查看请求方命名空间内已获授权的请求，显示尝试顺序和终态，不汇总成独立审批权限。

### 模板目录、版本与审批名单

- `/templates`：展示可使用的模板标题、用途、可用版本；请求方入口为“用此版本新建”。管理入口仅给有模板管理权限的人，不等于其有批准资格。
- `/templates/:id/versions/:version`：清楚分离不可变内容（schema、展示字段、认证要求）与可调整的当前资格名单。展示版本历史及只读对比，不把旧请求自动升级。
- 发布流程“编辑新版本 → 校验 schema
  → 预览载荷 → 发布确认”；schema 失败、版本并发冲突保留输入。发布说明新版本影响新请求，不改既有请求。
- 审批名单修改显示增删差异及“立即影响该版本待处理请求”的确认；不能只用“保存”隐藏此后果。列表成员以稳定 ID 区分同名身份。
- 停用模板只禁止新请求，已有 pending 按固定版本继续处理；确认中展示此范围。名单、发布与停用分别记录操作者和审计，不能默认产生全域权限。

### 身份、外部绑定与 Agent

- `/identities/me`：显示 Gate ID、人类/Agent 类型、启用状态和外部
  `(issuer, subject)`
  绑定；邮箱仅辅助识别。新增绑定要求重新认证和所有权证明，绑定冲突不按邮箱自动合并。
- `/identities/agents` 与
  `/identities/agents/:id`：显示自己有权管理的 Agent、负责人、认证状态、现有 Grant 和最近活动；“创建 Agent”明确提示不会自动继承创建者权限，下一步可单独签发 Grant。
- 注册 Agent 后签发认证材料，只展示一次并要求用户确认已安全保存；示意不生成真实 token。关闭后不能找回明文，允许重新签发/轮换。短期访问 token 与用于获取 token 的注册凭据分开展示，不把它们当成业务授权。
- 轮换提示旧材料何时失效；失败不得先声称旧材料已撤销。封存 Identity 确认不可复用 ID、停止未来操作但保留历史；不能误删除证据或自动改写凭证。
- `/login`：显示可用认证提供商，登录后回到允许的原页面。step-up 说明需要的认证强度与待执行动作，失败可重试/取消；不以勾选框冒充 MFA。未登录、绑定冲突、已封存、无提供商各自明确。

### Delegate 与 Grant

- `/authority`：分为“我拥有的 Delegate”和“授予我的 Grant”，显示固定范围、状态、接收身份、起止时间；无权限不显示管理动作。权限摘要按操作与模板/资源显示，不只给一个无法理解的 JSON。
- `/delegates/new`：选自身可委托权限的子集 → 核对范围 → 创建；显示所有者和默认禁用转委托。超范围由服务器拒绝，并保持输入，不自动放大/缩小成另一个授权。
- `/delegates/:id`：范围与所有者只读，调整范围用“创建替代 Delegate”；确认旧 Grant 不会自动迁移。停用展示影响的未来操作，不重写历史。
- `/grants/new`：先选 Delegate，再选稳定接收 Identity、有效期，展示 actor/owner/grantee 区别。过期、停用、超自身权限和时间范围均阻止签发，采用明确时区和绝对时间。
- `/grants/:id`：状态区分尚未生效、有效、到期、撤销与上游失效；显示授权依据和历史。撤销使用内联确认，明确不可恢复，延期必须新签发；列表刷新不能把撤销失败显示成成功。
- 第一版转委托关闭，不提供看似可用的转委托开关。

### 凭证验证、导出与审计

- `/verification`：输入凭证、调用方预期摘要、可信来源的 trust-bundle；逐项展示协议/outcome/签名/摘要/keyId/快照版本与时间。预期摘要必须独立来自调用方载荷，禁止自动填入凭证声明的摘要来制造匹配。
- 不提供无效 JSON/未知版本的成功结果；区分拒绝、不匹配、签名失败、泄露密钥、快照过旧与可放行。页面可作在线辅助，但真正离线验证由独立验证器完成。
- `/requests/:id/credential`：固定 Decision 信息、签发状态、下载入口；待签发说明无需重新批准，失败提供状态刷新而非“再决定”。只下载获授权的凭证，不连带导出全量载荷或其他请求历史。
- `/audit`
  与事件详情：按有权查看的 subject、时间、actor、authority、动作筛选，顺序展示不可变事件；显示实际操作者、权限主体、Grant/Delegate 与当时证据，明确区分“当时有效”和“当前已撤销”。
- 审计读取权不默认包含载荷读取权；受保护字段做缺省遮蔽并解释，无权字段不从 API 下发。初版提供逐请求证据查看，不增加未经确认的全库导出、删除、修改历史或管理员绕过。

## 状态、视觉与可访问性

| 状态                | 体验                                                 |
| ------------------- | ---------------------------------------------------- |
| 未登录深链接        | 登录后回到请求；回跳地址限定同源允许路径             |
| 加载 / 空列表       | 可读加载状态；空待办与加载失败分开                   |
| 字段错误 / 载荷过大 | 对应字段附近解释，保留未提交输入                     |
| 会话或权限失效      | 清晰说明与恢复入口；不暴露未授权载荷                 |
| 幂等/决策竞争       | 显示真实已存在请求或终态，不能静默重建               |
| 网络/服务故障       | 可重试、相关标识、结果不明提示；日志不输出载荷或令牌 |

采用安静的工作台：中性色背景、清晰的正文与信息分组，强调色用于操作，橙色用于待处理/警示。业务详情占主区域，权限与结果侧栏辅助核对；不做营销首页。中文优先，技术 ID 可复制但不作为主标题。

桌面支持列表/详情分区，320px 起单列；长标识换行，JSON 在自身区域滚动。键盘顺序与阅读顺序一致，焦点清晰、确认取消后返回触发按钮，状态使用 aria-live 且不只靠颜色；支持减弱动画。

## 初版与审阅证明

初版先做创建、待办、详情决定、撤回和凭证状态；其他子页面按身份、授权与签发能力落地，不以设计图表示已实现。不做批量审批、复杂流程编排、组织管理、通知中心。静态示意覆盖七个代表场景；后续生产测试必须额外证明 schema 校验、幂等、撤回竞争、失效权限、step-up、无权限深链接和签发恢复。示意交互不等于端到端证明。

## 示意校验

2026-10-14：两个场景均以本地文件方式在 1440px 和 320px 浏览器中验证并目视检查；无页面/场景横向溢出或内嵌纵向滚动。验证了场景链接、独立打开、载荷展开、键盘确认、取消焦点恢复、竞争结果和重置；没有浏览器脚本错误。这些结果仅验证示意，不能代替真实审批与授权测试。

2026-10-14 子页面补充：七个场景共 14 组桌面/移动布局检查通过；五个新增场景可独立打开，撤回/名单/停用/材料/封存/撤销示例的键盘展开与取消焦点恢复通过。新建核对保留原始输入，六种验证结果示意正确区分可放行与拒绝、不匹配、泄露、旧快照及无效签名。新增场景已截图目视检查，无浏览器脚本错误；真实创建、身份认证、授权、签名和下载不在此示意中执行。
