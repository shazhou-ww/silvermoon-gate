# Implementation

## Design context

设计材料归属 Ideal World，本文件只维护执行计划和验收标准：

- [业务模型](ideal/Business-model.md)
- [目标 UX](ideal/UX.md) 与 [体验示意](ideal/ui-review/index.html)
- [技术选型](ideal/Tech-stack.md)

本轮重新设计不以已有半成品为约束；原 D1 原型不能作为新授权模型及原子写入不变量已经完成的证明。

## Steps

### I-S01: 实现带版本的请求与模板行为

依据构想设计实现带版本模板、业务 schema 校验、固定载荷与幂等请求；使用 D1 原子 batch、条件写入与约束保护授权判断、唯一终态、Decision、审计与签发 outbox，证明撤回/决定/权限失效的竞态正确性。

依据 [UX.md](ideal/UX.md)
实现创建、我的请求、待我审批与详情确认，服务端提供授权分页；显式处理重复提交、撤回和竞争结果。静态示意不是生产能力。

### I-S02: 定义身份与委托权限

明确 Identity（身份）、不可变的 Delegate（委托权限）范围、有时限的 Grant（授权）、委托限制、操作者归属、认证方式，以及提交决策时执行的授权检查；界面明确展示实际操作者、权限主体和失效状态。

### I-S03: 定义凭证与审计边界

明确载荷规范化方式、签名凭证声明、离线验证和密钥状态语义，以及状态与审计记录的原子持久化和受保护载荷的处理方式；界面区分决定结果与凭证签发/恢复状态。

## Acceptance criteria

### I-AC01: 请求具有确定的结果

请求在 D1 中固定模板/schema 版本与规范载荷，保证请求方范围内幂等、动态资格和单一终态。通过目标 Worker/D1
runtime 的 schema、幂等、授权、撤回/决定/资格撤销竞争、batch 全回滚与审计/outbox 原子性测试证明；SQLite 测试不能代替 D1 排队、过载或读副本一致性证明。

浏览器测试证明创建、重复提交、确认和撤回竞争显示真实状态；桌面与 320px 布局可键盘操作且无横向溢出。静态示意不是这些能力已完成的证明。

### I-AC02: 委托操作可追溯且受限

经过审查的授权模型能够区分操作者、Delegate 和 Grant，并拒绝已过期、已撤销、超出范围或不允许的传递式委托；通过授权测试、审计示例和权限失效/无权限深链接浏览器测试证明，不泄露未授权载荷。

### I-AC03: 凭证能够验证预期决策

独立验证方能够验证标准签名凭证，要求载荷摘要与预期值精确匹配，并报告所用信任包版本；通过跨实现测试向量、密钥状态案例和数据库一致性测试证明。

浏览器测试证明凭证待签发、失败和恢复状态明确，拒绝签名不被误认为批准，失败不显示为成功。
