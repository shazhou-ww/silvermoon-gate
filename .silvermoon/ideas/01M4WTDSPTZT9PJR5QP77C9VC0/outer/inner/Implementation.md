# Implementation

## Design context

本契约仅覆盖 [MVP 路线](ideal/MVP-roadmap.md)
的最终阶段增量，前置三个 MVP 已分别交付人类审批、Agent 接入和离线凭证。依据
[业务模型](ideal/Business-model.md)、[UX](ideal/UX.md) 与
[技术选型](ideal/Tech-stack.md)
扩展，不重新实施全部前置功能；历史与原型不能替代验收证明。

## Steps

### I-S01: 完成有界委托与强认证

实现固定范围 Delegate、有时限 Grant、失效/撤销检查及模板要求的 MFA；将权限证据与实际 actor/authority 原子纳入决定和签名声明，第一版禁用转委托。

### I-S02: 补齐最终管理与审计体验

交付模板版本/名单、身份绑定/封存、Agent 轮换、Delegate/Grant 管理及授权证据界面；权限管理不自动赋予载荷读取或审批权。

### I-S03: 验证累积闭环与历史兼容

验证委托资格竞态、签发恢复、旧直接授权历史/凭证的兼容性，并回归前三轮的人类、Agent 与离线调用路径。

## Acceptance criteria

### I-AC01: 委托操作可追溯且受限

目标 Worker/D1 授权与并发测试证明过期、撤销、越界、身份封存及不允许的转委托被拒绝；实际操作者、权限主体和授权证据正确冻结。

### I-AC02: 管理与认证界面不扩权

浏览器测试证明 MFA/绑定/轮换和权限管理正确处理失败，无权限不能读取或管理载荷；桌面/320px 键盘流程可用。

### I-AC03: 完整服务不破坏前轮结果

跨实现凭证、迁移与端到端回归证明人类/Agent/离线闭环仍可用，旧直接权限证据不被改写；泄露密钥、不匹配和拒绝均不放行。
