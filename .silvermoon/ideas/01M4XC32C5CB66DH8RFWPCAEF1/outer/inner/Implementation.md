# Implementation

## Design context

依据 Ideal World 的 [业务模型](ideal/Business-model.md) 与
[详细设计](ideal/Design.md)
实施。细化包括禁止自审批、固定测试业务 schema、数据库条件授权、operationId 关联的唯一终态证据，以及失败/切换身份的缓存边界；本轮只是补设计，未完成下面条目。

## Steps

### I-S01: 实现直接身份与请求事实

实现人类稳定身份、一个固定业务 schema 的版本模板、直接审批名单，以及 D1 幂等请求、条件终态与原子审计。使用最终设计的身份/摘要边界，不提前实现委托或凭证。

### I-S02: 实现最小审批界面

用 React 与 shadcn/ui 交付登录、创建、我的请求、待我审批和详情确认；错误、无权限、结果不明与竞争终态明确显示。

### I-S03: 验证在线安全闭环

覆盖输入、访问控制、幂等、决定/撤回竞争、审计回滚与重启后的持久化。

## Acceptance criteria

### I-AC01: 请求与审计保持一致

目标 Worker/D1 测试证明单一终态、幂等冲突与 batch 失败全回滚；不能仅以 SQLite 适配器代替目标运行时证据。

### I-AC02: 人类可安全完成审批

浏览器测试以两个身份完成创建/批准/拒绝/撤回，第三身份无权读取；桌面/320px、键盘确认与错误恢复可用。

### I-AC03: 结果可追溯且不夸大保证

历史记录固定载荷、版本、操作者与时间；重启仍可读取，页面与接口说明不提供离线或 MFA 保证，以测试与界面证据证明。
