# MVP 2：让 Agent 等待人类审批并安全恢复

## 问题

只有人工页面无法让 PGH/Agent 工作流复用审批，需要一个认证明确、结果不明时不误放行的在线接入闭环。

## 结果

一个真实调用方以自身 Agent 身份创建请求，等待人类直接审批，核对在线批准结果与预期摘要后恢复自己的工作流；拒绝、撤回或无法查询则不恢复。

## 边界

- 继承 [MVP 1](../../../../01M4XC32C5CB66DH8RFWPCAEF1/outer/inner/ideal/Idea.md)
  的请求/人类 UX；允许在其外部 OAuth/云端试点受阻时并行推进本地设计及经批准的本地实现，但本阶段真实试点部署和现实世界验收仍须等待 MVP
  1 外部门禁及对应验收完成，不授权云写入或宣称前置已完成。
- Agent 拥有独立稳定身份和短期 token，创建关系不授予权限；本阶段只用显式直接授权，不实现 Delegate/Grant 或 Agent 自审批。
- 调用方负责阻塞/恢复，Gate 不执行业务；此阶段仅支持可信在线查询，不提供离线签名验证、Webhook 或全量 Agent 管理后台。

设计候选见
[详细设计](Design.md)（含认证、直接权限、兼容迁移、调用方示例与本地/外部证据边界）；具体设计经父会话审阅后再进入本地实现，不自动记录生命周期决定。

## 验收标准

- 一个 PGH/Agent 调用方用独立身份创建并追踪请求，人类能在已有界面处理并识别请求来源。
- 调用方只对 online
  approved 且预期摘要匹配恢复；重复创建、断网、拒绝、撤回、token 失效均不误放行。
- 试点真实执行“Agent 发起 → 人类决定 → 调用方恢复/保持阻塞”，审计区分调用方身份与审批操作者。
